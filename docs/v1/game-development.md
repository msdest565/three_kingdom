## 1. 产品目标与范围

以三国武将“一招横扫千军”为中心，做能单手操作的竖屏塔防。低伤军营减速聚敌并处理幸存精锐，玩家判断何时发动无双；刀波清掉普通步兵，精锐和首领留给军阵、协战与后续技能处理。采用更密集的真实兵潮，让无双前的逼近压力与无双后的空出防线形成可见变化。爽感来自看清战局后兑现一次大范围击破，而非无条件每秒清屏。

## 2. 玩家循环与一局节奏

局外从章节图选关，查看敌兵、路线、地形加成与推荐练度，选择已拥有武将、领衔与协战，再调整装备。进入战斗后由免费盾营、弓营建立初始防线，玩家花军粮补营和升级。波次清空后选择一项局内战术，随后继续守阵。最终波全部敌军退场且城关尚存即胜利，领取首通、新增星级差额和解锁，再去下一关或调整队伍。

普通关战斗时间目标为 3–5 分钟，幕末关 4.5–6 分钟；布阵、战术选择和阅读剧情暂停战斗时钟。时长是内容预算，不能超过时间自动判胜。故事开场控制在两句，可跳过；收束一句，首次解锁另有短卡片，重复通关默认折叠。

### 战斗速度与时间规则

支持 1×、1.5×、2×循环切换，按钮始终写出实际速度。默认 1×；用户选择可本地保存，首次教程期间固定 1×且禁用切换，教程完成或跳过后恢复已保存选择。暂停、布阵和战术选择不推进，后台返回先保持暂停，不补跑离开的时间。

敌军移动、出兵、塔与武将攻击间隔、怒气、六秒恢复、持续伤害、减速和技能队列都使用同一战斗时钟。相同战斗秒和相同操作时机，在三个倍率下应得到相同规则结果；1.5× / 2×仅减少现实等待时间，不额外送怒、不改变伤害和奖励。关卡的 240 战斗秒理论对应 240 / 160 / 120 现实秒，另加暂停、读剧情和选择时间。

音乐、音高、音效限流、按钮确认、横扫数字和提示阅读时长使用现实时间。无双命中可触发约 0.30–0.42 现实秒的短慢动作，只临时缩放战斗推进，保留玩家选择的 1× / 1.5× / 2×及按钮文字，结束后恢复选择；不得重复伤害、延长技能命中账本或改变音高。减弱动态模式关闭慢动作及强动效。计时器显示战斗用时，测试记录同时保存倍率变化与现实用时，避免把两倍速下两分钟误标为关卡节奏减半。

### 密集敌潮与无双主导

V1 各波规划人数在上一设计基础上增加到约 1.6 倍，同一出兵窗内增兵；这是新增真实敌人，不用装饰小兵冒充战斗单位。每波三兵团保持波峰和短缺口，配合盾营和投石减速形成可扫的队形。步兵承担大面积清潮，骑兵、重甲和首领保持自己的反制身份，不以普通兵血量同步放大抵消清场效果。

投石与火油的范围伤害、攻击频率收敛，投石基本命中带有限减速。盾营重点为维持聚敌，不承担大规模杀伤；多个减速取最强并按兵种抗性及速度下限计算，不能叠成永久停步。弓营额外箭和贯穿降低伤害系数，避免用强化组合恢复自动清屏。精确值与升级成本以数值文档为准；新增敌数带来的军粮必须单独审计，不能简单按旧比例宣称经济平衡。

可见指标为真实在场人数、待入场人数、无双覆盖预览和实际横扫数字。同时在场上限 160，容量满时保留待出兵队列、阻止清波；先降低粒子与装饰，不能隐藏敌人、删兵或提前胜利。指定 mode6 建设策略、正常解锁和三核心推荐下限已完成实际新账号连续六十关通关审计；四个关闭大招的对照关分别失败，具体版本、策略与数值见交付检查记录。仍需扩大队伍和种子，并验收真人无双时机、漏兵压力与操作体验。

前三关应让玩家依次感受“营阵能守”“我的无双能清”“第二武将能补”。魏 1–2 限一名出战，通关魏 2 后进入魏 3 时开放第二阵位，可用初始曹操协战；进入魏 9 时开放第三阵位。魏 3 首通另解锁夏侯惇和投石营。单将仍是合法编队，战前锁定精锐/首领血量系数 1/1.5/1.9，不因带更多人提高普通步兵血量、人数或速度。

| 阶段 | 体验任务 | 反馈与验收 |
| --- | --- | --- |
| 开局 | 有免费防线，补一个军营 | 一次点按布阵、一次选营；不在计时中读长文 |
| 首招 | 敌人聚到有效区域，怒满后点无双 | 就绪、起势、刀波、实际击破各有清晰反馈 |
| 中盘 | 精锐幸存，升级和协战有价值 | 不把精锐未死解释为技能失效 |
| 强化 | 对已建军营或已上场武将做选择 | 不出现完全无效卡，不重复已选卡 |
| 首领 | 两秒预警，清杂与单体收尾衔接 | 首领死亡但护兵未清不能提前胜利 |
| 结算 | 看见星级、奖励和下一目标 | 按幂等规则领一次，不强迫看广告 |

武将在城关后固定阵位持续普攻，无个人血条，不受敌兵直接击杀。张辽骑阵与赵云枪影为技能投影；夏侯惇跳跃、许褚前扑仅改变绘制位置，真实阵位不移动。夏侯惇跳出期间暂停普攻，0.9 秒后恢复。城关是唯一基础败局资源。关羽处决仅适用于 infantry 且不免疫的普通步兵；骑兵即使属于 ordinary 类也始终走数值伤害。各技能的形状、对普通/精锐/首领伤害、命中上限与控制衰减以数值数据为准，不以名字推断额外机制。

领衔开局怒气 40，协战为 0；三人分别有 100 上限和 6 秒施放后恢复期。有效交战时每秒分别增加 4 / 2 / 2，无敌目标和战鼓光环不单独建立交战。击杀、塔数、装备不会使回怒无限放大。

底部保留一个大领衔按钮，协战仅在战场右下角显示圆形头像浮层：一名助阵一个头像，两名助阵在角落小范围并排，透明背景，不占整列或挤压战场。按钮 46×46 CSS px，保留怒气填充与就绪高亮；技能名和恢复/队列状态通过无障碍标签与提示提供，不在角落堆成长文案。原武将阵位与技能原点不移动。默认全手动，战前可逐个开启协战自动；点按头像即自动选区施放，无需拖拽瞄准。

所有可选区域以当前合法可攻击人数为第一排序，人数相同才比较精锐/首领及近城权重的目标价值。关羽、张飞、赵云、许褚的方向技能使用几何边界角区间扫描，在各技能原有合法角度范围内求最大覆盖；人数和价值同分时优先最接近自身正前方，再采用稳定顺序，无目标保持正前方。自由圆区使用全体敌兵及各自碰撞半径求最大覆盖，不再截取 48 个目标抽样；同分再比较目标价值和群中心。现行技能分别采用曹操掷旗圆区、夏侯惇限距落点圆区、司马懿三处延迟雷区、刘备沿路向外推进、孙权城门向外半圆、周瑜/甘宁真实道路条带，不能恢复为旧的统一自身圆区。具体 shape、范围和真实命中时刻见 [数值设计第 4 节](balance-design.md#4-十五名武将的基础攻击与技能身份)。张辽、吕蒙比较合法路的覆盖人数；太史慈仍选最多三个不同目标。延迟和持续技能按当前位置选区，不预知未来出兵。预览每 0.2 秒最多更新一次，以淡描边提示覆盖，不显示未实际发生的击杀数；按钮点按时重新计算并锁定实际方向。关羽原型保留居中同分规则。

十五位无双强化各自的起势、主要形状、命中与收束，仍共享有限的粒子、残影和文字预算。真实 `damage` 事件驱动数值跳字与短受击，真实 `kill` 事件驱动倒地、兵甲落地与消散；死亡残影不能继续挡路或受伤。密集清场优先保留首领/精锐数字和少量普通兵数字，击破大数字按 castId 汇总真实击杀，一次技能只展示一次，不把预览人数或伤害人数当作击破数。

需要战术升级的波次清空后，先让当前技能起势与已排队请求播放完成，再冻结战斗，额外保留 1 秒可见的现实时间，随后显示三选一。等待时不出新兵、不推进怒气与战斗时钟，保留击破数字与音效尾声；不受 1×/1.5×/2×影响，后台、隐藏页面和遮挡期间不扣观看时间。不会等待持续火场或伏兵的完整寿命，以免拖长清波节奏；新局/离场清除未完成的弹窗等待。

关羽的移动刀波按当前路径、速度、减速/眩晕与已生效增速短程预估抵达位置，以最大有效覆盖选向；同收益时尽量留出角度余量，避免碰撞边缘刚好相切而在抵达前落空。预估不读取未来出兵或随机数，实际判伤仍使用当时的真实坐标。未知的新控制变化和队列延迟仍可能使目标离开，因此按钮标注“预计覆盖”，结果弹窗只显示已完成击杀。

手动请求入队时锁住当前预览，队列中目标走出可能造成部分落空，界面明确显示“待施放”。公共队列最多三请求，每人最多一个；预留怒气，起演才扣除，失败或自动条件失效则归还。相邻技能起演至少间隔一秒，主演出锁 0.9 秒，战斗继续推进；火场、伏兵与风牢的持续时间不阻塞下一人。协战自动在起演时重查目标数量和首领可攻击状态，避免对无敌目标空放。

幕末提供一名可选剧情借将，占出战位、使用固定关卡预设。借将不改永久库存、不送可拆装备、退出后清除。已拥有同名武将时可用自己的培养版本；一队禁止同 heroId 重复，未选借将也能继续。

## 4. 军营、敌兵与地图

| 军营 / ID | 核心作用 | 限制与取舍 |
| --- | --- | --- |
| 盾营 shield | 更低近距伤害、较慢攻击，主要减速并聚敌 | 不封死道路，首领/车抗控制 |
| 弓营 archer | 廉价连续输出，处理普通兵 | 精锐爆发有限 |
| 弩营 crossbow | 稳定针对重甲和首领 | 单轮目标少，不能替代清潮 |
| 投石营 catapult | 低伤、低频抛物线爆炸并有限减速，每石最多伤六人 | 爆圈其余敌人只受减速，留兵潮给英雄 |
| 火油营 fire_oil | 必经处低频持续灼烧 | 补伤与留敌，不替代英雄大范围清潮 |
| 战鼓营 war_drum | 范围军营增益与抗扰选择 | 无直接攻击，独放不会产生有效交战 |

剧情每营最高三级；无尽最高五级并有 L5 质变，L1–L3 基础值保持相同。外观和面板逐级变化。军粮只用于本局，剧情用于建造和升级，无尽另用于刷新选卡，不能兑换局外资源。战前显示解锁状态；战中仅提供已解锁类型。点地图营位或底部布阵入口选位，再建造/升级，面板打开暂停；无战中搬营、退塔刷退款或额外升级分叉。军营射程和地形加成在选择时可见。

常规敌兵为步兵、骑兵、重甲、扰阵弓手、军旗手、攻城车。它们分别构成清潮、速度、单体耐久、暂时军营干扰、群体提速、高漏伤压力。章内按教学节点逐步引入，首领复用破门、冲刺、召兵、坚壁、扰营五母型。干扰目标和首领行动均有可见预警，不能凭屏幕外事件突然扣城关血量。

12 地图母版提供实际不同的路线和营位；六十关复用母版，变动出兵方向、兵种配比、波段时序、首领与叙事。路径始终可见，战中不突然改道，芦苇不遮危险敌军。中央高台、河堤和顺风火油的指定加成独立 10%，战前和营位中都要写明，不能把装饰水面推断成未说明的敌速效果。

当前关卡配置有 516 个显式波次，每波三个兵团。波内计数已经包含成长段数量倍率，运行时不可再乘一次。首领有独立生成时间线；普通兵出完不代表首领尚未生成时可以提前清波。下一波必须等待本波待生成和在场对象都归零。

## 5. 剧情与主线结构

采用“军师演武沙盘、三国英雄录”。玩家重演三方守阵问题，篇章按势力划分，默认魏 → 蜀 → 吴线性开放；剧情为原创架空推演，不宣称历史战役结局。英雄录将跨时期人物转为可选择的阵谱，使玩家能够带喜欢的名将重打其他章节。

魏篇五幕：乡野起兵、兖州守土、官渡粮道、北境风雪、合肥坚城，重心为粮道、阵形和精锐。蜀篇五幕：乡野护民、长坂救援、蜀道开关、汉中争锋、荆州守望，重心为护民、山路与协战。吴篇五幕：江东继业、江夏舟道、赤壁火阵、南郡水寨、濡须江垒，重心为水岸、持续火力与三路。

每幕四关，第四关有架空敌军统领与收束；武将解锁随故事推进。对话包含 speaker、text、portraitId 与可选 voiceId，文本本地化独立于规则。死亡表现只代表本次演武败退，不写成玩家已收藏武将永久阵亡。三卷结尾保持完整，未来第四卷添加新序章，不改写已完成结局。

## 6. 培养、装备与奖励

局外三资源：经验册每本 50 XP，铜钱用于等级/技能/装备，精铁用于装备。人物等级只缓慢增强本人普攻与技能数值，技能等级只增强被标注数值；不扩大战术控制时间、不改变关羽普通兵处决和回怒规则。材料不足时显示本次成本、缺口与已有资源，允许取消，不弹付费补齐。

四槽装备为武器、铠甲、兵符、战马，等级 0–10、白/蓝/紫/红/金五品质，固定词条，无随机洗练。武器增强本人伤害，铠甲增加全队城关最大耐久，兵符增加军营伤害，战马仅扩大本人普攻射程。详情直接说明收益对象，不引入武将生命值或战马走位。普通白至红装备可锻造与升品；金色仅十五件专属武器，只能由胜利箱取得，可强化，不能锻造或升品合成。十五匹红色专属坐骑 S11 可锻造，关羽赤兔属于该池。

装备有唯一实例 ID，可在战前跨武将转移；来源槽为空，替下物进背包。空槽等价白装 Lv0，不补发装备。专属武器/坐骑仅本人激活额外效果，其他武将仍享普通品质与强化收益；未穿戴物可分解，已穿戴物不能分解。开战锁定装备与科技快照，战斗中不接受换装。

六营科技各 Lv0–10、消耗铜钱和精铁。伤害营满阶自身数值伤害 +25%、射程 +15；战鼓满阶在覆盖内给军营伤害 +2%，同类取最强。科技不改攻击间隔、范围伤害人数、处决资格、控制或回怒；投石基础保持 3 秒攻击间隔、每石最多伤害 6 人。完整成本、开放门槛、十五套专属装备与概率见 [成长扩展设计](progression-design.md)。

每次胜利一箱，包括重复挑战和超出每日材料奖励软上限的胜利，失败无箱；每箱一件 Lv0 武器。白/蓝/紫/红/金概率分别为 45%/30%/17.5%/5%/2.5%，金池十五件等概率、没有保底。胜利事务抽取结果、入背包并保存，开箱仅揭示已保存结果；重复 win、刷新、重复点开与同 battleId 重放不能重复发箱。满仓只回收本次新掉物并显示所得，不覆盖旧装备。

每位首次获得武将发四件白品质 Lv0 基础装备（满仓无空间的槽为空）；新将另一次性免费升到解锁段与账号最高已达段的推荐最低等级较大者，最高不超过本版 Lv30。追赶不发可重复经验，也不免费送技能级和进阶装。拥有初始曹操、关羽，默认首次只让关羽领衔；第二阵位开启后提示曹操协战。

推荐培养指三名选定主力与主要武器，其他装备槽是可选优化。全十五人满级或十二槽全满不是主线门槛。每个成长段必须用进入该段之前已到手的首通资源审计最低培养；只证明六十关总奖励足够仍不合格。若段内资源不足，应降低推荐门槛、提前发确定资源或调整段曲线，不能以每日刷取弥补必要缺口。

首通按 levelId 一次；一星通关后开放下关，二星城关剩余至少 60%、三星至少 85%。二/三星各新增 10% 首通基础资源，逐项向下取整，可一次三星领齐或以后补差额；保存最高已领奖星级。重复奖励每天全账号前三次胜利可得，本地日期仅作单机便利限制，改时钟可以绕过，不能用于线上反作弊或商业化资源核算。联服后由服务端日界与领取记录取代。

结算计算成一个事务：验证清关 → 生成未领取首通与星差额 → 增加资源并发一次胜利箱 → 解锁武将/军营/阵位 → 更新领取账本与最高进度 → 保存一次。重复触发 win、刷新结算、重放同 battleId 不得再次发奖。失败保留局外进度，没有资源负扣；重试不再播放完整教学。

## 7. 新手引导与音频

主线开发版沿用并接入首次自动引导：守关说明 → 实际部署或升级 → 等待蓄怒 → 实际施放 → 显示真实清场结果。说明、部署、怒满提示和完成卡暂停；蓄怒及刀波兑现推进战斗。引导允许跳过，首页和暂停页可重看。引导不凭空赠怒、造假击破或强迫新账号先通训练场；首关 prerequisite=tutorial_available 表示入口已可用，不表示必须完成。

V1 延伸采用按解锁节点的短提示：魏 3 第二将与投石；魏 7 弩营与精锐；魏 9 第三将与队列；首次培养说明资源和槽位；蜀 1 战鼓；吴 1 火油。每个 guideId 保存版本、已展示和完成标记；版本升级只呈现新机制，不对所有回流玩家重放整套开场。

主线开发版音频使用原创 Web Audio 合成：菜单、战斗、首领、结算循环音乐；盾击、箭声、投石发射与落地、武将普攻、刀波、真实命中、军卒倒地/兵甲落地、击破、布阵、升级、战术、受击和胜败提示。`damage` 使用短撞击，无双命中可增强低频；`kill` 增加短死亡层，精锐和首领更沉，不播放逐兵长尖叫。三类死亡全局最小间隔为普通 0.12、精锐 0.18、首领 0.28 现实秒，命中层为 0.075–0.10 秒；音效总声部上限 18，精锐/首领优先于普通声部，不能抢占无双与胜败主重音。敌 ID 去重缓存上限 512，声音按事件位置左右声像，不延迟补播被限流的敌兵。音乐与音效分别开关并保存；暂停/选择停止战斗声，静音停止音效声部，后台停止全部声源，返回只恢复一个音乐播放源。

音频在用户手势中解锁，失败时保持游戏可玩；这是浏览器自动播放策略要求的实现边界。[MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay) 当前合成音乐用于试点；完整版精修音频的时长、音量、循环和许可见美术文档。没有加入未经授权的流行歌曲、影视配乐或配音。

## 9. 工程结构与内容契约

当前代码是原生 ES modules，无第三方运行依赖。V1 沿用可独立模拟的规则引擎，拆分职责后再决定是否引入框架；配置不能直接解释为任意脚本。各模块以 JSDoc 类型、纯函数边界和 Node 测试约束输入输出。

| 模块 | 职责 | 不应承担 |
| --- | --- | --- |
| ContentRepository | 加载 manifest、字典、关卡；验证引用和兼容版本 | 在战斗中隐式抬高旧关难度 |
| BattleEngine | 固定时步、出兵、道路进度、伤害、状态、胜败 | DOM、音频、联网或永久发奖 |
| HeroSystem / SkillQueue | 个人怒气、技能命中账本、目标选择、队列 | 让特效回调决定伤害 |
| CampSystem | 建造、等级、射程、控制、军粮消费 | 修改局外铜钱 |
| ProgressionService | 培养成本、装备归属、解锁与结算事务 | 相信客户端线上付费凭证 |
| SaveRepository | 本地存档校验、迁移、原子更新与备份 | 把校验和当成防作弊 |
| Renderer | 程序绘制/图集、插值、反馈、降级 | 修改敌人生命或产怒 |
| AudioSystem | 用户手势、总线、事件混音、生命周期 | 每帧创建 Context 或每个击杀播放一声 |
| PlatformAdapter | H5/TapTap 能力封装与降级 | 把未接入的平台登录当作成功 |
| AnalyticsAdapter | 本地调试日志、经用户知情的运营事件 | 采集聊天、联系人或无关设备信息 |

逻辑采用 1/60 战斗秒固定步长，输入现实帧间隔上限 0.1 秒，按倍率积累后分解为最多十二个子步（2×时），保存未满一步余量；不能将 0.2 秒直接送入引擎再被其 0.1 秒上限截断。暂停、界面阻断和后台清除积累，隐藏时不补算离线敌潮。固定种子仅驱动战术抽取与明确随机事件，记录 contentVersion、buildVersion、种子、队伍及配置才能重放。手机帧率与规则时钟分离。

当前模块位于根目录：campaign-app.js 负责剧情/无尽 UI，campaign-state.js 负责培养与存档，v1-engine.js 负责战斗与技能，v1-renderer.js/hero-portraits.js 负责程序绘制。无尽纯规则、专属、专精、羁绊分别在 endless-rules.js、roguelike-system.js、hero-upgrade-*.js、camp-upgrade-*.js、synergy-*.js；endless-milestones.js 与 endless-telemetry.js 负责奖励计划和本地统计；tactic-art.js 与 roguelike-presentation.js/.css 负责新增表现。docs/v1/data 的两份 JSON 通过 scripts/build-runtime-data.mjs 导出为 runtime-data.js；禁止直接编辑生成模块，改源 JSON 后运行 npm run data:build。上表是职责契约，不表示存在同名独立类。src 分层、版本化资源包与远程 manifest 属于后续扩展方案；TapTap 与联网分析适配尚未接入。

## 10. 存档、迁移与数据安全

保留原型 wushuang-guard-v1 保存纪录、音频设置与教学版本。当前主线已使用 wushuang-guard-campaign-v2 与 schemaVersion=3，上一有效存档保存在 -backup 键；迁移先备份旧数据，读取原型音乐/音效/纪录/教学与倍速偏好，不将原型胜利数兑换主线奖励。schema 2 旧品质 white/green/blue/purple 迁移为 white/blue/purple/red，保持原档数值、强化等级、资源、进度、编队、奖励账本与统计幂等；科技从零开始，不补发旧胜场宝箱。导出、导入检查预览与确认替换已接入设置页。

示例是设计字段节选，不是可导入的完整存档；当前英雄 equipmentIds 为槽位到物品 ID 的对象，还包含 accountId、progress、交易与发奖账本等校验字段。完整结构以 campaign-state.js 和实际导出为准。初始资源、基础装备与英雄由初始化事务生成；零值不是数值事实源。inventory 每件含唯一 itemInstanceId、templateId、slot、quality、level、equippedHeroId，槽位只引用合法唯一物品。培养先验证等级门槛与全部材料再扣款，失败不部分扣资源。

以 snapshot+revision 存一次完整状态；写前验证、写后可读回，保留上一有效备份。未来存档版本不认识时只读提示升级，不自动降级覆盖。允许导出带版本的 JSON，导入检查大小、结构、整数上下限、ID、装备归属和领奖记录，先预览再替换，失败保留旧档。清空进度属于用户主动设置操作，须明确二次确认。

本地存档可被修改，校验和只能检测损坏。首发不建立竞技排行榜与真实财产系统。未来账号采用独立 IdentityProvider，云存档先解决版本冲突和离线合并；消耗/领取使用服务端事务与 requestId 幂等。新增账号不可直接信任从本地导入的资源用于商业化或排行，应明确迁移奖励政策。GitHub Pages 公共仓库与包中不得出现 API 密钥、平台 Secret、管理员权限或个人测试存档。

## 11. 长期运营与扩展规则

contentVersion、buildVersion、saveSchemaVersion 分别演进；数值补丁可不改存档版本，新增存档含义必须提供迁移。每次发布附 changelog、影响关/英雄、校验结果、资源许可、回滚方式与负责人。旧 ID 不复用，删除内容标 deprecated 并保留旧存档显示映射。界面读取 chapter.levelIds，不写死三个章、二十关或十五英雄。

新增篇章至少提交新章简介、关卡清单、剧情收束、路径与营位、波次、成长段、奖励、英雄/军营引用、资源包、存档迁移与校验。第四章可用群雄卷或支线卷作题材提案，具体内容另立规格；不得直接把既有 S01–S12 抬高迫使老玩家补练。技能接口按 heroId 注册 handler，新增技能必须包含目标、伤害类别、时钟、命中上限、取消和自动判定契约。

活动目录与常驻关独立：eventId、levelIds、startsAt、endsAt、eligibleProgress、rewardDefinition、rewardClaimVersion、contentVersion。单机试点使用永久挑战与本地公告，不做声称服务器可信的限时福利。真正限时、补偿、签到和排行榜上线前需具备服务端时间、账号和领取记录；活动关闭不删除已有装备或常驻进度。

| 运营阶段 | 内容方式 | 必需能力 / 退出条件 |
| --- | --- | --- |
| 原型试点 | 关羽训练关，收集首招理解、按钮和音频反馈 | 基础回归、用户可导出反馈记录 |
| 魏篇内测 | 四地图与三将、培养闭环 | 每段资源、配置迁移、低档手机性能通过 |
| 完整 V1 | 三篇六十关、十五人、装备 | 全关可通、资源不强迫日刷、许可与发布资料齐备 |
| 内容运营初期 | 用已验证母版做战术挑战、修复反馈 | 先完成一次小内容更新和一次回滚演练 |
| 联服与商业化 | 云存档、限时活动、可选商业化 | 独立规格、平台能力、可信结算和客服准备 |

发行后建议每 4–6 周评审一小批挑战或体验修复、每季度评估新增主题章。它们是排期节奏，不是已承诺每周期都生产一整章。先以实际制作人日、玩家留存和回归成本决定内容量，运营预算包含程序、美术、音频、测试、授权、平台资料和客服。长期收藏可以补齐十五人和装备上限，不以每日上线领资源惩罚休息玩家。

故障分类：无法进入/存档损坏/重复扣款（将来如有）优先；阻断关卡与错误发奖其次；表现与轻微数值随后。先定位 build/content/save 三版本，停止错误内容入口并回滚完整配置。补偿按事故和账号记录一次发放；无账号的单机版本提供修复导出/导入流程，不能承诺远程修复无法识别的本地档。

日志事件至少包括 session_start、tutorial_step/skip、level_start/end、ultimate_cast/burst、camp_build/upgrade、tactic_select、hero_unlock/upgrade、equipment_upgrade/equip、save_error、asset_load_error。共同字段为版本、模式、关卡 ID、匿名会话、练度与队伍；仅调试版记录逐敌数据。线上收集先提供用途说明和关闭方式，试玩期不上传任何个人身份或设备精确标识。

指标用于检验问题：首招是否被理解、首次引导完成/跳过、每关重试、无双真实击破分布、主力更换率、各段资源缺口、存档失败、加载与帧时间。没有数据时不写“已达留存目标”；种子胜率和真人留存分开报告。

## 12. GitHub 试点与 TapTap 适配

GitHub 仓库 https://github.com/msdest565/three_kingdom 是当前源代码和文档入口。npm run build 输出独立 dist/index.html 可双击离线体验，也能用于静态试玩部署；本次不自动提交、推送或发布。正式开发保留源目录，设计阅读器位于 docs/v1/index.html，避免把所有源文件只留在一个 HTML 中。

GitHub Pages 适合当前静态试玩，长期商业化上线应另评估正式托管与条款。[GitHub Pages 使用限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) 资源路径以当前项目目录相对路径构建，不能假设部署在域名根目录。缓存采用版本化文件名，旧资源保留到兼容窗口结束；不要将自动缓存升级作为无法回滚的全局替换。

TapTap 官方将 H5 和 TapWebGL 接入方式分别说明，当前 Canvas/DOM H5 需要走对应适配验证。[TapTap 官方开发入口](https://developer.taptap.cn/agents/) PlatformAdapter 预留 init、getIdentity、load/save、share、visibility、capabilities；不支持的能力返回明确 unsupported，单机继续运行。TapTap 试投前验证宿主音频、存储额度、返回键、加载域、分享与审核资料，具体 SDK 按届时官方文档接入。

不能把“小游戏”视为已确认免软著的发行途径：当前通用审核规范列有软件著作权及素材授权等资料要求，H5 的具体适用范围仍须在该产品后台核对，并纳入发行预算。[TapTap 审核标准](https://developer.taptap.cn/minigameapidoc/tap-operation/operation-standards/review-standards/) 这是发布前验证事项，本次完成设计和本地体验不依赖其办理。

## 13. 验证、性能与开发里程碑

首场美术/音频资源加载目标 5–10 MB，按本场英雄与地图拆包，不当作平台硬限制。参考低档手机目标稳定 30 fps、中档 60 fps；常态 60–120 敌兵、压力 150、硬容量起点 160。容量满时显式排队出兵，仍计入待生成，不能丢敌或让规则变快；如队列延迟破坏密度/时长目标，应重排该关出兵，并记录实测。粒子、模糊、尾迹与装饰先降级，命中、怒气和路线保留。

| --- | --- | --- |
| M0 原型体验修订，本轮 | 教学、三营音效、四场景音乐、倍速、密集兵潮与低伤控制塔、离线包 | 引导/音频/速度/老记录/生命周期及无双对照回归通过 |

## 14. 文档维护与决策台账

每项改动要写目的、受影响 ID、状态、验证方式和负责人，状态使用设计/实现/验证/发布。数值 JSON 和关卡生成器为各自事实源，五份设计文档组成阅读器；成长扩展文档由 scripts/generate-progression-docs.mjs 生成，运行 npm run docs:progression 更新，设计阅读器为生成产物。改数值后重跑派生检查、关卡生成、交叉检查和阅读器生成，再审查差异；不要手改已生成六十关表格后丢失来源。

当前已定并已接入：15 武将、3×20 剧情关、6 军营、最多三将、四槽培养、剧情演武，以及无尽 P0–P5 的全部功能。需继续实测：真人长局、技能与卡牌曲线、兵潮密度、资源收益、首招时间、同屏容量与真机性能。后续另立规格：正式商业化、云账号、限时活动、PVP、专用横屏、武将时装。实现完成不等于已发布或已平衡。

文档就地维护当前规则；已实施且不再被测试依赖的旧提案与重复截图可删除，关键决策集中到 [开发记录](../DEVELOPMENT-HISTORY.txt)，避免新 AI 重读相互矛盾的阶段档。测试依赖的基线与迁移说明必须保留。内容制作模板最少包括范围、故事、玩法、稳定 ID、数值引用、资产、奖励、兼容、检查、发布时间与回滚。

## 15. 已实现的肉鸽无尽

V1Game.reset() 以 options.mode === 'endless' 启用独立规则，剧情仍读取固定 60 关的显式波次、原战术和三级军营上限。无尽以 80 波为目标里程碑，城关存活可继续；波次在 endless-rules.js 程序生成，独立数值参考为 `node docs/data/endless-curve.mjs`，不能用文案近似值替代脚本结果。L4/L5 基础值与质变仅在无尽可用，局外科技按当前等级基础值加成。

实际卡池为 26 属性 + 42 军营专精 + 60 武将专属 + 8 羁绊，共 136 卡；原 22 战术 ID 保留。卡按有效武将、已建军营和羁绊资格过滤，稀有度/类别加权；每波清空后三选一，可付军粮刷新、跳过得军粮、单局三次锁定。可重复属性卡不受普通战术一次上限限制，收益按卡片 decay 递减，城墙卡 decay=1。史诗和武将专属有候选保底，传说连续未出现时加权，并非保证第 12 次一定获得。

四羁绊使用桃园结义、魏武雄风、江东虎臣、卧龙冢虎的修正名称；八组合击由两位武将有效技能在战斗时间窗口内真实命中同区触发，共享单局次数。奖励仅在首次达到新里程碑时永久领取，80 波两箱的金色概率为各 5%，不改剧情胜利箱 2.5%。85 波起每五波有首次突破铜钱奖励；重导旧档不能重领或重抽。调参记录仅本地保存，既有普通事件日志仍有界。

选卡界面使用整个可用游戏高度，三张卡及刷新/跳过无需滚动；锁位于每张卡右下角，44×44 触控区，默认开锁透明底，锁定闭锁金底，具有可读标签和按下状态。已检查 360×640、320×568、320×510，136 卡长文案均参与检查。后者是选卡专项短屏检查，不代替完整游戏真机矩阵。

表现已接入 61 符号合成卡面、11 个新音效事件、八组合击、三段无尽听觉变化与八类动效，详见 [美术设计](art-design.md)。所有新动效消费 reducedMotion；静态保留稀有框/角标、合击名号、真实范围和城墙红闪。最新自动验证基线为 54 个测试文件、486/486 通过；日志只证明其覆盖的规则/浏览器夹具，真人 80 波体验、手机帧率、外放听感和 TapTap 宿主仍待验证。
