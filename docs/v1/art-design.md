# 无双守关 V1 美术与音频生产规范

更新日期：2026-10-12。适用对象：角色、场景、UI、特效与音频制作，以及 H5 集成验收。V1 设计范围为魏蜀吴各 5 位武将、各 20 关，共 15 武将与 60 关；12 个地图母版支持独立关卡的路线、障碍和节奏变化。战场最多同时显示 3 位武将，采用领衔 1 位与协战 2 位。军阵为盾、弓、弩、投石、火油、战鼓 6 类，每类 3 级。

**V1可玩开发版已接入**。当前已有十五张原创程序 SVG 头像（hero-portraits.js）、十五位固定阵位 Canvas 武将轮廓、十二种地图主题、六类三级军营及技能程序效果（v1-renderer.js），声音由 Web Audio 合成。目标是让玩家先看清敌潮与防线，再感受无双清场。沿用墨绿、金赭与卷轴质感；这些程序资源用于可玩开发版，不等于精修位图角色、逐帧图集或录制配乐。生产规格继续保留，真实手机及 TapTap 宿主视觉/音频验收尚未完成，来源见 [素材记录](../ASSET_LICENSES.md)。

[可编辑 SVG 风格板](art-style-board.svg) 与 [PNG 阅读版](art-style-board.png) 展示布局、色板、轮廓与无双节奏。它是生产参考，不是已完成的游戏美术；图中轮廓样例用于比较角色辨识方向。原型基础参见 [游戏设计 v0.1](../game-design-v0.1.md)，其单关和局外范围已由本次 V1 扩展。技能机制以 [数值基线](data/balance.json) 为准，地图名称、路径、营位和使用数量以 [关卡数据](data/levels.json) 为准。

剧情使用军师演武沙盘重演三方战役，默认魏 → 蜀 → 吴共 60 关线性推进，卷宗按势力演阵而不按史实时序。允许跨历史时段和跨势力组队。建筑、服饰与武器遵循统一的三国演义架空语言，地图主题名和武将搭配不宣称历史还原。保留关羽原型不占 60 个主线关卡。十五人程序头像与战场轮廓已接入，精修美术、生产动画及完整版配乐尚未完成。

## 1 视觉方向与辨识原则

采用略带俯视的 2D 战棋视角，人物身体压缩、头部略放大、兵器轮廓夸张。背景用成片的低对比色块、少量纸纹和山石树木表现国风关隘；角色用清楚的实色边缘与局部亮边，避免给每名小兵绘制无法在手机上辨认的纹饰。

第一层辨识是敌我：我军偏青绿，敌軍偏朱红，并同时用盾形、旗帜和移动方向辅助区分。第二层辨识是职能：盾营有成排盾面，弓营有弓弧，投石营有高杠杆；骑兵具有横向马身，重甲兵具有宽盾与方肩，首领具有更高轮廓与独立血条。第三层才是纹样、衣甲质感与历史装饰。

关羽保留绿色战袍、红面、长髯与大刀四个识别点，刀刃在小尺寸下仍应形成大弧。周瑜用窄袍、扇形或火令轮廓与赤金火效；张飞用宽肩、长矛与深色体块；赵云用窄身、银甲、长枪与蓝白拖尾。不得靠换衣服颜色代替不同武将轮廓。

| 用途 | 色值 | 使用规则 |
| --- | --- | --- |
| 深墨与面板底 | `#203933` / `#192F2A` | 背景边缘、轮廓、文字承托面板 |
| 我军主色 | `#276B57` | 军阵、主将、所属标识 |
| 无双亮色 | `#77CEB0` / `#D6FFDF` | 刀波与就绪提示，小面积高亮 |
| 金赭强调 | `#E4C27A` | 主按钮、资源、关键边缘，避免铺满战场 |
| 卷轴浅色 | `#EEDFB3` | 文字、弹窗和牌签 |
| 敌军朱红 | `#A23D37` | 旗帜、普通兵、敌方威胁；不得单独作为危险标识 |

图标以两档线宽和少量实心块组成。普通装饰不使用无双的近白亮色。文字采用系统中文字体；需要交付专用字体时，将字体许可与体积列入资源清单，书法字不可替代资源数值和按钮说明。

## 2 世界坐标与屏幕适配

逻辑战场保持 `420 × 600`，左上角为 `(0,0)`。当前原型主将位于 `(210,550)`，城关入口约在 `(210,530)`。V1 三将阵位统一为领衔 `(210,550)`、协战 `(140,548)` 与 `(280,548)`，对应 `balance.party.heroPositions`。原型六营位分别为 `(53,142)`、`(367,142)`、`(67,290)`、`(353,290)`、`(88,420)`、`(332,420)`。V1 每张地图配置 6–8 营位与 2–3 条固定路线；地图层在不同屏幕动态扩展可用安全区域，保持玩法坐标与 UI 操作区的映射。地图与武器效果均使用坐标制作锚点示意，不把本图坐标烘焙进角色资产。

保留原型按 Canvas 实际宽高分别缩放世界坐标，地形和人物都会随战场比例改变。V1 已使用独立等比尺度绘制人物、图标、文字和圆形标识，位置仍按世界坐标映射，地形允许适度拉伸。该适配已通过 Node 回归，真实设备布局与视觉验收仍待完成；精修资源仍待生产，接入时需同步验证渲染与点击映射。

| 层级 | 尺寸与约束 |
| --- | --- |
| 逻辑地图底图 | 420 × 600 逻辑像素；源稿至少 840 × 1200，图层分开交付 |
| 角色与军阵 | 在逻辑坐标定位，显示比例等比；不要把脚底阴影和文字标签合并进角色图 |
| 顶部 HUD | 固定 CSS 尺寸，参考总高 100–112 px，加顶部安全区；仅放血量、军粮、波次、暂停等常看信息 |
| 技能操作区 | 底部领衔无双按钮至少 56 CSS px 高；两个协战在战场右侧竖排，触控高度至少 44 CSS px，避开营位及安全区，自动开关在战前编队中配置 |
| 关键触控 | 目标至少 44 × 44 CSS px，主要按钮建议 48 px 高；相邻按钮至少 8 px 间隙 |
| 文字 | 核心说明与按钮至少 12 CSS px，资源与主按钮 14–18 px；战场短标签至少 11 CSS px，不能只以 11 世界像素验收 |
| 安全区 | 使用 `env(safe-area-inset-*)`；按钮、击破数字和弹窗内容不得被刘海、圆角、手势条覆盖 |

营位触控范围与视觉底座分开。逻辑点击半径 34 属于保留原型；V1 已按实际缩放保证至少 44 CSS px 的触控直径，重叠时选择最近营位，并保留底部布阵入口。命中规则通过 Node 回归，真实设备触控可达与相邻营位选择仍待验收。短屏压缩装饰、说明和间距，长屏增加战场空间，不把无双按钮推离底部。

验收视口包括 360 × 640、390 × 844、430 × 932 CSS px，并覆盖有安全区的机型、浏览器工具栏展开与收起、200% 文本缩放及横屏返回竖屏。横屏先保持竖屏游戏区域居中，若做专用横屏布局再单独排期。

底部保留领衔主按钮的视觉优势，两个协战在战场右侧竖排，各自有头像、怒气/恢复状态与简短技能名；就绪显示高亮边框和“就绪”，不只依赖颜色。协战默认手动，战前可选择自动；领衔不自动。不要把三个技能叠在同一个无法判断归属的进度条上。界面区分就绪、排队、演出中与恢复期，排队不重复消耗怒气。三位主将同屏时，协战身体可比领衔缩小约 10%，不减少兵器辨识。全队施放队列的起始间隔至少 1 秒、主演出锁约 0.9 秒，持续火海等效果不占用后续演出锁；叠加期间降低旧特效尾迹亮度。每次只显示当前施放者的一个技能标题，不能连续用三个全屏演出遮挡战场。

养成 UI 包括势力分组武将列表、武将等级与升级、编队领衔/协战选择、装备详情与背包、章节关卡图、活动入口。武将详情需要战斗胸像、等级与主要数值、技能卡、4 个装备槽位；装备槽为武器、铠甲、兵符、战马。装备首轮只生产图标与品质边框，不生产 15 位武将乘装备组合的换装动画。品质同时标注名称/符号，不只换色；资源不足、满级、已装备与替换确认使用统一组件。

势力配色是列表和剧情上的归属标识，战斗中玩家队伍始终共享青绿所属提示。跨势力组队不能让曹操或周瑜因朱红/紫色服饰看起来像敌兵；脚底所属标识与头像框共同区分。

`hero-portraits.js` 的 `PORTRAIT` 是头像和战场唯一造型来源；`HERO_ART` 只存姓名、势力、单字与技能名元数据。武将大头 Q 版，身体约 46 世界单位，头占约 37%，兵器超出身体，外轮廓统一 2px `#100c09`。己方脚下青玉环保留怒气弧，领衔环更大；默认不画头顶字和名牌。首次见到显示姓名 3 秒后淡出，之后点按阵位或键盘聚焦技能按钮显示 2 秒。首次见面记录为独立 UI 历史，不进入战役存档。

六营底座分别为盾营方栅、弓营圆土台、弩营六边石台、投石营长方夯土台、火油营焦黑石圈、战鼓营高台。军营兵统一青玉尖帽、身体用营色，等级用 1/2/3 面营色旗表示；默认无名牌，选中时才显示。攻击接实际 `attackFlash`：盾墙前推、弓手满弓、弩臂回弹、投石臂甩起、火盆冒焰、鼓槌落下。升级复用底座与状态帧，强化技能使用独立特效组件。

V1 六类军阵的三级视觉增量为：盾营增加盾面/拒马，弓营增加弓手/齐射旗，弩营增加弩臂/箭匣，投石营加大杠杆/弹药架，火油营增加油罐/火盆，战鼓营增加鼓架/旗杆。弓营必须有弓弧与站立弓手，弩营必须有水平弩架；火油的火苗是低亮暖色，战鼓的增益用短金绿环。三级无分支，不额外生产每条战术的整套军阵。

## 4 动画状态与帧预算

动画按游戏行为生产，不套用固定九状态。普通敌军沿路线前进，主将驻守，军阵固定攻击。首轮使用单一向下偏俯视的战棋角度，移动方向由位置和兵器朝向表达；若产品要求三方向角色，再把方向数 `D` 从 1 扩为 3。非对称兵器、旗帜和服饰不可无条件镜像。

| 类型 | 必要状态与参考帧数 | 播放与事件点 |
| --- | --- | --- |
| 主将 | idle 6、attack 4–6、ultimate 8–12 | 怒满复用 idle、速度 1.3 倍并给兵器描金；普攻出手对齐引擎攻击事件，短攻速按比例压缩；无双对齐真实命中时刻 |
| 普通、骑兵、重甲 | walk 6，受击和死亡由独立反馈叠加 | 普通兵尖红盔与高矛，骑兵马头前伸，重甲塔盾；外描边普通 1px、精锐 1.4px |
| 扰阵弓手、旗手、攻城车 | walk 6，行为反馈只在实际事件触发 | 宽檐斗笠、高旗、屋顶撞木保持头顶或外轮廓可读 |
| 首领 | walk 6，五类母型各自缓存 | 高冠和红色威胁环，保留五类首领的差异兵器；1.4px 墨描边 |
| 军阵 | 每类 idle 4、attack 5 | 按六类底座、等级和真实攻击状态缓存；默认无文字，选中显示名牌 |
| UI 与地图 | 状态切换、旗帜轻动、少量草木摆动 | UI 优先程序过渡，旗帜 4–6 帧或程序形变；不循环播放整张背景 |

动作帧按状态与 DPR 预渲染到离屏 canvas，战斗时复用 `drawImage`；没有位图文件或远程素材。玩家武将没有独立 HP，不生产血条或死亡复活动画。夏侯惇跳跃、许褚前扑、张辽冲锋为纯绘制位置，不改变真实坐标或点选阵位；减弱动态时去掉位移与拖影，只保留原地起手、收势和范围/命中状态。实际命中与治疗不等待样机里的示意动作。

司马懿 0.3 秒指画，1 秒落雷；武将动作锁仍为 0.9 秒，施法出手与延迟命中分开记录。吕蒙 0 秒布雷，敌人接近时结算。关羽、张辽、刘备、孙权的前锋从 0 秒开始；张飞、许褚、太史慈的即时技能在首帧显示出手，赵云三穿对齐 0/0.25/0.5 秒，周瑜、甘宁与诸葛亮的首次持续伤害在 0.25 秒。

敌兵列位只用于渲染：`(enemyId * 7) % 5` 对应道路法线方向的 −12/−6/0/+6/+12 偏移，奇数列沿路径切线错开 4。同路局部 40 单位内超过 6 人时横向乘 1.4、上限 ±17；重甲、攻城车、首领固定中列。按偏移后的 y 排序，血条、闪光和死亡残影跟随绘制位置；引擎碰撞、道路进度、命中与点选仍用真实坐标。160 人对比基准记录 Canvas 同步绘制耗时，不能替代真机 GPU 帧率验证。

提交动画时同时交付事件表：状态、帧数、FPS、循环方式、脚底锚点、武器挂点、出弹帧、命中帧及可打断规则。临时摆动动画不得改变碰撞半径、路径或真实技能覆盖。

## 5 地图与图层

每张地图交付可编辑分层原稿和分层导出，按下面顺序合成：地表与纸纹 → 路线与浅车辙 → 低地表物 → 营位底座 → 按脚底 Y 排序的敌军、军阵、主将 → 投射物与命中特效 → 刀波 → 城关前景允许遮挡部分 → 界面标签与击破提示。

树冠、城楼和旗帜是否遮挡角色要逐个标注。敌军到达城门的最后 60 逻辑像素必须看得清；城楼屋檐不能把突破者藏在后方。营位周边预留 34 逻辑像素的选择区，常看信息不得贴近高频粒子区域。道路视觉边界须包含实际路径和横向队列偏移，不让小兵在看似不可行走的山石上穿行。

## 6 无双与战斗特效

关羽无双按当前原型约 0.76 秒的推进刀波建立首轮时间轴。真实伤害以战斗引擎事件为准，特效只解释已经发生的覆盖和命中；产品调整技能时同步更新事件表。

| 时间 | 视觉与声音 | 遮挡和操作限制 |
| --- | --- | --- |
| 0.00–0.10 秒 | 主将压身提刀、局部青绿蓄光；低频起势音 | 主按钮即时反馈，不锁住全屏；地形与敌群仍可辨认 |
| 0.10–0.26 秒 | 刀刃出光、短促宽弧、首次命中；斩击重音 | 无双震屏约 6 逻辑像素、约 0.38 秒衰减（表现力优先，已确认放宽原 3px / 0.26 秒上限），同时 1.03 倍径向缩放冲击约 0.22 秒与约 0.35 秒的屏幕边缘玉青/朱砂色差闪光；不使用持续全屏闪白 |
| 0.26–0.76 秒 | 刀波沿锁定方向推进，击破旗帜与小量消散粒子 | 亮刃窄、尾迹透明，仍能看见重甲和首领；覆盖范围与引擎宽度一致 |
| 0.76–1.20 秒 | 余辉淡出；界面只出现一次最终横扫数字 | 普通兵跳字限额，精锐/首领优先；结算完成后立即显露幸存者和下一路压力 |

无双命中采用约 0.30–0.42 现实秒的短慢动作反馈，保留玩家选择的倍率及按钮文字，结束恢复选择；音频、输入确认和提示维持现实时间。减弱动态关闭慢动作、震屏、缩放冲击、边缘闪光、强闪和数字弹跳。慢动作只影响推进，不增加伤害或技能命中次数。

助阵控制缩为右下角的圆形头像浮层，每个头像 46px，单将一个、两将小范围并排；保留就绪亮框与怒气填充，去掉侧栏背景和长技能文案，战场恢复全宽。升级遮罩与布阵面板盖在头像上方。清波时先播完当前起势与已排队演出，战术三选一再等待 1 秒可见现实时间，保留刀光收束、倒地和击破数字的观看空间；后台不消耗这段时间。

十五位无双均加强起势、武器/阵法轮廓、真实命中与收束，方向、圆区、枪影、箭雨、火场和伏兵应可辨。选区预览以合法最大覆盖为准，同人数再目标价值，方向同分居中、自由圆区同分靠群中心；固定自身圆区和合法路线不得因表现扩大，详细规则见开发设计。范围线与实际判伤一致。跳字只消费真实 `damage` 的 amount，倒地/短兵甲散落只消费真实 `kill`，不能用预览伪造命中。敌兵死亡保留短倾倒与淡出残影，不能再次受伤或挡路；按真实 castId 击杀总数显示一次大数字，持续技按实际结算展示。

普攻只使用小型青金亮点，盾营以脚底短环显示减速，投石以低亮度尘圈显示范围。每次升级用一个局部金色环和短标签，波次使用一个横幅。大招名称与最终击破数字分别只有一个显示来源，防止 Canvas 和 DOM 同时重复提示：武将切入与技能名由 DOM 切入层显示，Canvas 只做震屏、缩放冲击和边缘闪光，不再绘制第二个标题。地图名与地图规则只在 DOM 战场提示条显示，Canvas 顶部不再绘制地图名。

### 密集敌潮与倍速表现补充

战斗支持 1× / 1.5× / 2×，顶部速度按钮文字明确，首次教程固定 1×。速度提高的是规则时钟，音乐、音效音高和阅读提示维持现实速度；普通攻击、命中和死亡音效按现实时间限流，避免两倍速形成噪声。短慢动作不会覆盖玩家所选倍率，起势确认、短余辉和最终横扫数字需可读，视觉尾迹不重复伤害。

本轮敌数提高到约原设计 1.6 倍，所有增加的可攻击单位都对应真实敌人。HUD 增加真实在场数，待生成/待入场与在场分开，不能把未来兵数标成已在场。敌军绘制可按稳定 enemyId 做轻微横向/队列错位，提高兵器与旗帜可见度；偏移只能改变表现，碰撞、攻击与覆盖仍用逻辑位置，偏移保持小于角色可辨半径。首领、重甲和近城危险目标优先保持轮廓与血条。

低伤投石命中的尘圈配减速短标识，表现为敌群步速放缓，避免沿用巨大爆炸闪光误导其伤害。盾营以队伍步速变化体现聚敌。画面应看见“密集逼近 → 点无双 → 大片倒地消散 → 幸存精锐”，普通兵跳字按预算合并或舍弃，最终横扫数只展示一次。压力场景先减粒子/闪光，不减少真实敌人或隐藏残兵。

首轮性能上限按同屏 160 敌人做压测：每名普通兵死亡粒子最多 4 个，粒子池初始上限 160，命中火花同时上限 32，伤害跳字与死亡残影均使用有界池。具体池容量以渲染实现和交付记录为准，真机测量后调整。音效总声部上限 18，普通命中和死亡先限流，不按 160 人生成 160 声部。优先降低粒子数量、尾迹和装饰，保留刀波覆盖边缘、敌将血条与技能状态。不要对每名小兵使用独立大模糊滤镜。

减弱动态模式读取 `prefers-reduced-motion`，并允许游戏设置覆盖：关闭震屏、缩放冲击、强闪（城门闪白、无双边缘闪光）、慢动作、界面缩放弹跳、落营弹跳和漂移文字；保留敌兵 80ms 命中闪白、城关裂纹、墨渍与射程环；保留静态范围提示、短淡入淡出、刀波行进、真实伤害数字与击破结果。该模式仍要体现清场，不用减弱动态换取不清楚的攻击范围。

## 7 文件组织与导出

建议源文件目录为 `art/source/{heroes,enemies,camps,maps,ui,fx,audio}`，运行资源为 `assets/{atlas,maps,ui,fx,audio}`。本规范只定义目录，不表示这些资源已经存在。共用组件按主题与用途管理，角色文件不得依赖其他角色的绝对路径。

命名格式为 `{category}_{id}_{state}_{direction}_{variant}`，使用小写英文与下划线。例如 `hero_guanyu_ultimate_front_base`、`enemy_armor_walk_front_red`、`camp_archer_attack_front_lv2`、`fx_guanyu_blade_main`、`map_pass01_gate`。ID 与显示中文名分开，新增皮肤只替换 variant，不能覆盖基础资产。

交付包含源稿、透明 PNG 帧或无损图集、atlas JSON、缩略预览、事件表与许可记录。图集先以每页 1024 × 1024 或 2048 × 2048 为目标；不把所有地图与音频打进一张总资源表。角色按公共敌军库和主将包拆分，初始只加载本次需要的主将、主题与关卡。

PNG 使用 sRGB、透明背景、标准未预乘 RGBA。素材制作端不要预先乘透明度；浏览器或 GPU 内部的预乘处理由加载渲染链路统一完成，避免二次预乘造成黑边。导出时透明边缘保持邻近有效颜色，图集留至少 2 个源像素 padding 和 2 个源像素 extrusion；过滤模式、trim、rotated、pivot、sourceSize 必须记录。自动裁切可以节省图集，但恢复帧必须使用源尺寸与统一脚底锚点，不能让角色跳动。

UI 矢量保留 SVG，禁止脚本与外部引用；可交栅格备用图。色彩和尺寸应在深底、浅底、缩小到实际显示大小时检查，不能只看 200% 源稿。首场资源 5–10 MB 是加载目标，不是平台包体规定；超出时先拆加载包、压缩背景和音乐，再减少辨识所需的角色帧。

## 8 音效与音乐制作 brief

战斗声音要让玩家闭眼也能区分“就绪”“出刀”“命中一群”“城门受损”。主将专属音色用短尾音和不同起势表达；不让密集小兵每次死亡都播放完整重音。

| 资产组 | 制作方向 | 参考长度与复用 |
| --- | --- | --- |
| UI 点击、取消、建造、升级、战术选择 | 木片、轻钟或短鼓，触发清楚且不过亮 | 0.05–0.35 秒；共享 5 项，音高可小幅变化 |
| 弓箭、盾击、投石发射 | 弦响、木铁碰撞、杠杆低响，保持职能区别 | 0.15–0.50 秒；每类 1 主样与 1 轻变体 |
| 轻命中、重甲命中、群体击破 | 轻撞、金属短尾、旗帜与气浪复合音 | 0.10–0.60 秒；群体击破按每次技能结算一次 |
| 军卒、精锐、首领死亡 | 倒地低撞与兵甲短响；精锐更沉，首领增加低频收束 | 程序合成约 0.065–0.27 秒；全局分类限流，不播放逐兵长尖叫 |
| 主将无双起势与斩击 | 关羽：低鼓起势、金属刀风、低频撞击，少量非语言呼声可选 | 每主将 2–3 专属项，主重音 0.4–0.9 秒；语言台词单独立项 |
| 怒气就绪、城关受损、首领入场 | 提示钟、木门撞击、短号角；频率与攻击音错开 | 0.3–1.2 秒；共享提示，首领可增加专属项 |
| 胜利与失败 | 胜利短铜锣与明亮收束；失败低鼓与缓落尾音 | 1.5–3 秒；不覆盖结算按钮触感 |
| 战斗 BGM | 鼓点、低弦和少量笛箫，留出刀击中高频；战场紧张但不持续高密度 | 60–90 秒无缝循环；首轮共享一首，再按环境主题扩展 |
| 首领 BGM 或加强段 | 同主题更强鼓点，尽量复用和声材料 | 30–60 秒循环或可切换段；菜单曲为后续可选项 |

源音频交付 48 kHz / 24 bit WAV，音效尽量单声道，音乐立体声；发布格式与压缩码率由目标浏览器解码验证后选择。每个文件交付峰值、响度、循环起止与尾音长度；不强行截掉混响尾巴，不使用会产生点击声的拼接点。

首轮混音以主重音为最高可闻层：BGM 参考约 −20 LUFS，峰值不高于 −3 dBFS；短音效不强求同一 LUFS，按听感与峰值单独调。无双起势后 BGM duck 约 6 dB，20–40 ms 进入、250–400 ms 恢复；普通命中无需每次 duck。总线留余量，音效语音数设上限，密集命中优先合并。手机外放、耳机、低音量和静音切换都要验收。首次用户点按后解锁音频，后台切换暂停，恢复不叠加播放，分别保存音乐和音效音量。

当前原声音频由 Web Audio 纯程序合成，无外部音频资产。`damage` 与 `kill` 分别触发短命中及死亡层，位置映射左右声像；普通、精锐、首领死亡最小间隔分别 0.12 / 0.18 / 0.28 现实秒，命中 0.075–0.10 秒，最多 18 声部。有界敌 ID 去重防止重复死亡重播，超预算直接跳过，不积压延迟播放。普通层优先级 0，精锐/首领 1，无双/胜败 2；静音、暂停、选择与后台均阻止新战斗声音。倍速或慢动作不改变音高。Mock Audio 自动测试用于验证生命周期与声部预算，不能替代浏览器、耳机/外放或手机听感验收。

V1 三势力 BGM 共享基础器乐语言，通过魏的低铜与稳鼓、蜀的弦笛与急鼓、吴的水声质感与轻打击形成差异；可采用 3 首章战斗循环加 1 首共用首领强化段，地图母版不自动对应一首新曲。15 位专属音效重点区分剑、重斧、长枪、羽扇、火攻与弓箭，每位至少有独立起势或主重音，不能只改音高。三将按队列连续施放时，当前施放者重音优先，先前持续效果的尾音降约 3 dB，避免后续技能被淹没；不能用音频调度延后实际命中事件。

素材登记表至少包含 asset ID、作者、来源链接或合同、下载/交付日期、原许可文本位置、商用/修改/分发条件、署名方式、授权证明、修改说明与负责人。自己制作的音效记录作者和源工程；AI 辅助资源记录工具、生成日期、输入来源与人工修改。许可未核实的资源不进入发布包，不把系统字体名称等同于字体文件授权。

## 9 范围扩展与预算

用 `H` 表示主将数，`E` 表示普通敌兵种类，`B` 表示首领母型数，`V` 表示首领变体总数，`C` 表示军阵类型，`M` 表示独立关卡配置数，`S` 表示地图母版数，`D` 表示角色方向数，`U` 表示不复用的额外技能特效数。V1 固定 `H=15`、`E=6`、`B=5`、`V=15`、`C=6`、`M=60`、`S=12`、首轮 `D=1`。地图数量增加不自动增加主题、音乐和首领数量。

| 工作包 | 数量公式或扩展方式 |
| --- | --- |
| 主将角色与头像 | `H` 套战斗角色 + `H` 套胸像/选择卡 + `H` 套专属无双 |
| 敌兵与首领 | `E × D` 套动作 + `B × D` 套首领动作 + `V−B` 组外观增量；变体单列，不冒充新兵种 |
| 军阵 | `C` 套基础组件 + 每类型 2 组升级部件；强化沿组件复用 |
| 参考动画帧预算 | `28H + 14ED + 26BD + 16C + 20D`；20 帧为扰阵弓手射击、旗手号令、攻城车撞击增量；不含粒子与程序动画 |
| 地图 | 1 套共享关隘组件 + `S` 套主题组件 + `M` 份地图组合与遮挡配置 |
| UI | 1 套布局与组件库 + `H` 张主将卡 + `M` 张关卡卡/缩略图；图标按真实功能增量 |
| 特效 | 1 套共享普攻/命中/升级/危机效果 + `H` 套无双 + `U` 套独立技能 |
| 音频 | 约 18–24 项共享短音效 + 每主将 2–3 项专属音效 + 按独立首领追加提示；音乐先共享，再随主题增加 |

V1 最少交付 15 套战斗角色、15 套头像/胸像、15 套无双、6 种敌兵、5 首领母型与 10 组新增外观变体、6 套军阵基础组件与 12 组升级部件、12 套地图母版、60 份地图配置、3 套章节背景、15 张主将卡、12 张母版缩略底图、1 套养成/编队/装备 UI 组件库。参考角色与军阵动画预算约 750 帧，额外方向、变体专属动作或独立演出另算；逐帧、骨骼与程序复用的成本不同。装备图标按最终装备条目数 `Q` 生产；4 个槽位类型只定义形状，不能把 `15 × 4` 当作装备总数或换装动画数量。

先用人日与批准单价估算预算，不将参考工期当作外包报价。首轮规划模型为：风格与技术样机 4–6 人日；每位主将 3–5 人日；每类杂兵 1–2 人日；每位独立首领 2–4 人日；每类军阵及升级部件 1.5–3 人日；每个新增环境主题 2–4 人日；每张同主题地图组合 0.5–1.5 人日；UI 组件库 3–5 人日；每套无双特效 1–2 人日；共享音效库与首轮循环音乐 3–6 人日。逐帧精修、额外方向、配音与宣传立绘另算。

这些区间是内部排期假设，需拿关羽样机的实际制作速度校正。15 位主将仅角色包约 45–75 人日，15 套无双约 15–30 人日，12 母版主题约 24–48 人日；三项并行但不能压成一位主将的原型排期。养成 UI 扩展另留 5–10 人日；装备图标按批准的条目数与复用模板估算。预算公式为各工作包的批准工量乘单价，加明确授权费用和约 15% 返修余量。美术、音频、集成人日分开，发布资质和平台费用不包含在该公式中。

长期运营的增量单独立包：新增主将增加 1 套角色/头像/无双和 2–3 专属音效；新增同主题关卡主要增加配置、截图与障碍组合；新增主题才增加场景组件与音乐需求。活动皮肤只改变外观、头像和可选装饰尾迹，不改变技能判定、数值、所属提示或敌我辨识。皮肤需复用骨架与事件点，若必须换武器轮廓或动作则按新资源工作包计费。活动 UI 保持一个可复用活动面板和换皮图框，不每次重做整套首页。

## 10 生产顺序与验收

生产按可复用模块推进，扩展数量不改变第一批交付顺序。

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 风格样机，参考 2–3 个工作日 | 关羽与 3 类敌军黑白剪影、色板、营位底座、真实屏幕缩小图 | 无文案也能区分敌我、骑兵/重甲/主将；关羽大刀轮廓明显 |
| 关羽闭环，参考 3–5 个工作日 | 关羽起势与刀波、至少一种命中、地图分层、无双音效、UI 关键按钮 | 整局清场后能立刻看清幸存精锐；伤害范围与刀波一致 |
| 共享资产库，按 C/E/B/S 估算 | 军阵、敌兵、首领、主题组件、通用声音、图集与事件表 | 实际尺寸不跳锚点、不漏边、不因色变丢失职能 |
| 完成 15 主将与 60 关，按工作包分批 | 三势力角色、6 军阵、12 地图母版、60 配置、养成与编队 UI | 武将差异轮廓清楚，最多 3 将同屏可读，地图道路/障碍/营位与判定相符 |
| 集成验收，参考 2–4 个工作日 | 真机截图/录屏、帧率与加载记录、许可表、缺陷修复 | UI 点击达标，首场资源目标达标，减弱动态与静音/后台恢复可用 |

工期是工作包顺序和参考工量，未确认团队人数、敌军/首领/装备条目与单价前不填写固定上线日。总人日不是自然日，排期需考虑角色、美术集成和音频工作的并行条件。

验收必须使用真实显示尺寸：灰度下敌我和精锐仍可分辨；60 名敌兵交叠时道路、兵器和剩余首领仍清楚；无双瞬间普通模式无连续全屏强闪；减弱动态模式无震屏；文字、按钮、安全区和营位触控覆盖目标机型。图集检查透明边缘、锚点、重复帧、空帧和错误镜像；音频检查循环点击声、削波与多次恢复叠音；交付清单和授权登记必须与实际发布文件一一对应。

当前 SVG 风格板可以直接编辑颜色、布局与轮廓，适合讨论与外包 brief；成品验收仍需要在游戏内加载真正的生产资源与真机实测。

## 成长扩展界面与图标

军营科技页显示六营 Lv0–10、当前收益、下一阶成本、解锁条件和满阶状态；铁匠铺区分锻造、强化、升品，金专武显示“胜利箱获得”，不出现锻造或升金入口。背包展示装备名称、槽位、品质、等级、持有人、专属激活/未激活；换装预览应明确原持有者空槽及替下物去向，分解只针对未穿戴物。

品质统一为白、蓝、紫、红、金，名称与符号/边框共同表达，不能只靠颜色。金色开箱用低亮短光与物品名称确认，减弱动态开启时去除强闪、震屏与长尾迹，保留结果。箱内结果已经保存，揭示动画不触发再次抽奖。装备首轮只制作图标与品质框，不要求英雄换装动画。

图标按 balance.json 的装备 templates 事实源维护：当前 34 个模板（4 普通槽位模板、15 金专武、15 红专属坐骑）；普通品质边框复用，不把品质数或武将数直接乘成模板数。专属名称、效果与锻造规则见 [成长扩展设计](progression-design.md)。专属坐骑与武器的图标只表示物品主题，不改变战斗角色本体驻守契约。
