# 军营科技、铁匠铺与战利箱设计

当前可玩开发版，文档核对日期2026-10-20。规则事实源为 [balance.json](data/balance.json)。本章由 scripts/generate-progression-docs.mjs 生成；总体状态见 [当前状态](../PROJECT-STATUS.txt)。剧情与无尽的奖励规则分开说明。

## 军营科技

六条独立军营科技作为局外成长，不替代局内建造；剧情军营最高3级，无尽最高5级。每营科技Lv0–10，使用铜钱和精铁，研究时扣款，开战锁定快照。科技加成作用于相应等级基础值，但伤害/射程上限仍为25%/15；无尽卡牌是另行局内修正，不受科技上限合并限制。更换武将不会清空科技。

| --- | --- | --- |
| 盾营 | 自身数值伤害 +2.5%、射程 +1.5 | 自身数值伤害 +25%、射程 +15 |
| 弓营 | 自身数值伤害 +2.5%、射程 +1.5 | 自身数值伤害 +25%、射程 +15 |
| 投石营 | 自身数值伤害 +2.5%、射程 +1.5 | 自身数值伤害 +25%、射程 +15 |
| 弩营 | 自身数值伤害 +2.5%、射程 +1.5 | 自身数值伤害 +25%、射程 +15 |
| 火油营 | 自身数值伤害 +2.5%、射程 +1.5 | 自身数值伤害 +25%、射程 +15 |
| 战鼓营 | 光环内军营伤害 +0.2%、射程 +1.5 | 光环内军营伤害 +2%、射程 +15 |

研究目标等级 r 的铜钱为 120 + 60×(r−1)，精铁为 1 + floor((r−1)/2)。Lv1–10 分别要求已开放全局第 1/6/11/16/21/26/31/36/41/46 关，并且该类军营已解锁。每营从零到满级共 3900 铜、30 铁；六营合计 23400 铜、180 铁。

伤害科技独立乘一次 1+0.025×科技级，火油作用于真实每跳伤害；射程加值先计入再应用该营位地图射程修正。战鼓的额外伤害光环只作用于覆盖中的军营，同类取最强，不随鼓数量叠乘。科技不缩短攻击间隔、不增加范围伤害人数、处决资格、减速强度/时长或回怒。投石仍保持基础 3 秒攻击间隔，每石最多伤害 6 人；基础 Lv1 满科技单目标伤害 17.5。

无科技、无金装备也应能按推荐最低培养通主线；科技与装备掉落提供更多策略和重复挑战目标。增量验证需另记录“同一合法策略、开启科技”的军粮、技能贡献和通关时间，避免额外成长把英雄挤出战斗。

## 装备品质与铁匠铺

品质为白、蓝、紫、红、金，装备强化 Lv0–10。武器、铠甲、兵符、战马四槽有独立实例 ID，可在战前跨武将转移，原装备进入背包；来源武将对应槽可为空，空槽数值等于白装 Lv0。开战后当前战斗不接受装备变更。品质、物品名、强化级、已穿戴者与专属激活状态均展示。

## 剧情胜利宝箱与概率

剧情每次胜利恰好发一个箱，每箱恰好一件武器，重复挑战同关仍发；失败不发。每日前三次重复材料奖励的软限制不限制剧情宝箱。剧情各章节关卡使用同一品质概率；无尽首次里程碑采用下文独立规则，不按剧情胜场发箱。

| 箱内品质 | 概率 | 内容 |
| --- | --- | --- |
| 白 | 45% | 普通武器一件 |
| 蓝 | 30% | 普通武器一件 |
| 紫 | 17.5% | 普通武器一件 |
| 红 | 5% | 普通武器一件 |
| 金 | 2.5% | 十五件专属武器中等概率一件 |

掉落强化级统一为Lv0。金品质固定2.5%，金池内十五名将武器各占1/15，可掉尚未解锁武将的专属武器并先存背包。没有保底修正，每箱都是独立品质抽取；“平均40箱出一件金”是数学期望，不保证第40箱必出。连续60次胜利至少一件金的理论概率约78.1%，指定一件专武的每箱概率约0.1667%。

箱内结果使用独立于战斗种子的随机源，在唯一胜利结算事务中抽取、入背包并保存；开箱按钮只揭示已保存的结果。重复win、重复点击、刷新、同battleId重放不能再抽或多发。没有新增箱内奖励的付费入口。

背包上限4000件；达到上限只按回收表分解本次新掉物并明示所得，不覆盖既有物品。满仓解锁新将时没有空间的白装槽为空，避免阻断通关或覆写装备。铜钱/精铁在各自存档资源上限内增加。

## 旧存档与后续扩展

存档升级schema3，沿用wushuang-guard-campaign-v2键。schema2的白/绿/蓝/紫分别映射白/蓝/紫/红，保持各档原数值、强化等级、资源、已通关、编队和奖励账本；科技初始化零级，不为旧胜场追发宝箱，迁移前数据保留备份。较新版本仍只读保护，损坏存档可原样导出恢复。

无尽endlessMilestones为可选schema3字段，首次第10波前不因普通开局/选牌/失败新增该字段；领取通过CampaignStore事务，保留原子回滚、收据、防重与stale_save_revision检查。统计另存本地键，不上传。

新科技、装备模板、配方与掉落池沿稳定ID扩展；新增金池须明确单件条件概率变化，不能重命名旧实例所引用的模板。联服后由服务器决定箱内结果与交易幂等，本地试点不具备可信反作弊能力。
